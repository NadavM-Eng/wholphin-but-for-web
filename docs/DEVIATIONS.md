# Deviations from the TV app

This document lists every way Wholphin Web differs from the Wholphin Android TV app (v1.1.1, upstream commit 8dcf189), so a reviewer can see at a glance what is the same, what was adapted, what was left out and what was fixed.

Last updated: 2026-11-24 (second stage of the final merge, its repair and audit, the focus fixes after the audit, the TV-comparison pass, its merge into the app, the final check and repair, and the backdrop color fix, all of it on `main` since commit `e1b7e04`; then the polish round, on `main` since the merge commit `f1fb308`; then the two commits after it, `692715f` (values in right-to-left languages) and `7ad52ba` (touch on sliders and the reorder handle), with `main` at `7ad52ba`; then the release round of the same day (`93fe59c`, `6c14670`, `bf31148`) and the first public release; then the maintenance rounds of 2026-11-22 to 2026-11-24, with `main` at `509db33`; then the second public release of 2026-11-24 (phase 35); then the third release and the player changes of phase 40, then the episode change of phase 41 and the fourth release, with `main` at `5734cae`; see section 1.2)

Related documents: [README.md](README.md) (index), [PROJECT-LOG.md](PROJECT-LOG.md) (chronology), [DECISIONS.md](DECISIONS.md) (decisions), [ARCHITECTURE.md](ARCHITECTURE.md) (structure), [TOOLING.md](TOOLING.md) (tools and commands), [STATUS.md](STATUS.md) (current state), [spec/](spec/) (behavior specs extracted from upstream), [CLAUDE.md](../CLAUDE.md) (working agreement).

## 1. How to read this document

### 1.1 The four tables

Each area (section 3 onward) has up to four tables:

| Table | Meaning |
|---|---|
| Adapted for the web | The TV app does something that makes no sense in a browser as is. The web app does an equivalent thing. |
| Not ported, no web equivalent | A TV feature that was left out, with the reason. |
| Upstream bugs fixed rather than copied | The Kotlin source has a defect (or an obviously unintended behavior). The web version does the sensible thing and names the upstream file. |
| Additions the TV app does not have | Things that exist only on the web. |

If a table would be empty, the area says "none identified" instead of showing it.

### 1.3 How much each part has been checked

- Shell, setup and home (Main): built by one agent each, then reviewed independently (fidelity against the Kotlin, web quality, code, tooling) and fixed. Builders and fixers drove them in a real (headless) browser against the throwaway test server and, read-only, the real server. An integrator then ran the whole-tree checks and fixed nine more items (its report was not yet in the archive when the first version of this document was written; it is there now). The lead committed the wave in `b37c856`.
- Library browsing, detail pages, series pages, search and Home customization (Main, wave 3b): built by five agents, reviewed by six independent reviewers (fidelity for each area, web quality, code), fixed by four fixers (11 browse, 20 detail, 3 search and 8 polish findings) and then walked end to end by an integrator. Builders and fixers drove the pages in a headless browser against both servers at 1920x1080, 1280x720 and 390x844 with emulated touch. Two slips of the integrator's keyboard script wrote to the real server for the limited test account (a favourite and a watched mark); both were reverted and checked. Later briefs forbid sending keys or clicks to anything that writes on the real server.
- Fix pass (Main): three agents fixed open findings, widened the end-to-end suite and re-checked every built page in Chromium, Firefox and WebKit (the Playwright builds, headless, on Windows) at 1440x900 and 390x844 with touch on the throwaway test server.
- Playback engine and on-screen player (wave3a): the engine was built and run in Edge and Chrome against every test codec file and several items on the real server (results in `src/features/playback/engine/PLAYBACK_MATRIX.md`). The on-screen player was built afterwards, driven in Edge only, reviewed by three independent reviewers (fidelity, the playback matrix, code) and fixed (19 findings: 13 fixed, 3 rejected, 3 deferred).
- Settings, Seerr and the production server (wave3a): built, independently reviewed, fixed. The fixers re-ran the changes in a browser, except the production-server fixes, which were covered by unit tests only. The image was rebuilt and run later, at the branch gates (section 16).
- Live TV, music, photos and the screensaver (wave3a, wave 4): built by three agents (the photos builder also built the screensaver), reviewed by four independent reviewers, fixed (6 Live TV, 13 music, 8 photo and 2 merge findings). Every Live TV record or cancel action was answered by a test mock; none reached a server.
- Final merge, stage 1 (integration): one agent merged `wave3a` into main as it stood before the fix pass and wired the two halves together, two independent checkers examined the merged app and reported 24 findings, and a repair agent confirmed or rejected each one against the code and the running app. Its notes list 19 fixes, 5 rejections and 2 items deferred to the lead (some findings were split into parts).
- Final merge, stage 2 (integration): one agent merged main's fix pass into `integration` (17 textual conflicts, and the places where both sides had solved the same problem), three independent checkers (code seams, browser engines, user journeys) reported 31 findings, and a repair (cut off once by the model usage limit, then finished by a second agent) fixed 29 of them, rejected 1 and kept 1 as a recorded deviation. An independent auditor then re-checked the claims and found the branch ready to land, on condition that the test server's Live TV guide data be renewed. After the audit the lead renewed the guide tooling and ran the whole end-to-end suite; a timing race in one test and a real focus defect turned up, and a fixer and an independent verifier handled them (`docs/final-merge-notes.md` sections 8 to 10). Every browser in these checks was headless and muted; WebKit and Firefox are Playwright's builds.
- TV-comparison pass (parity): eleven area agents each compared their screens with the screenshots taken from the TV app in an Android emulator (230 picture pairs in all), measured the differences, fixed about 118 of them in their own folders and sent 96 requests to a shared-kit agent, which changed the shared components (`src/ui`, `src/app`, `src/theme`). Eleven independent checkers then looked at each area again (66 findings by count of their reports, 11 of them major), eleven fixers handled the findings, and an integrator brought the work together and fixed what was left in shared code. In the end 244 reference pictures were paired, and the pass's own gates were green (601 unit tests, the end-to-end suite 188 of 188 twice, the compare sheet 208 scenes ok, the crawler 390 pictures ok). Measurements were made in headless Chromium at 960x540 CSS pixels with 2 device pixels per CSS pixel, so one CSS pixel equals one dp and the pictures compare pixel for pixel with the TV screenshots; regression pictures were also taken on a phone width, in Hebrew and in other themes. Firefox and WebKit were not run in this pass beyond the end-to-end smoke projects. Its notes are `docs/parity-notes.md` (section 5 lists its deviations, section 6 what is still different).
- Merge of the TV-comparison pass (final): one agent merged `parity` into the audited app (13 conflicts) with the rule that the comparison pass owns how things look and the merged app owns how things behave (focus, keyboard, mixed-direction text, the room for the mini player, the playback session); independent reviewers reported three minor findings, all fixed (`docs/final-merge-notes.md` section 11).

## 2. What stays the same

These are the goals, so they are not listed as deviations below.

- Colors: the same 8 themes (Purple, Blue, Green, Orange, Bold Blue, OLED black, Red, Brown), dark only (upstream's light schemes are unreachable in the app), generated from the extracted theme data into CSS variables (`tools/gen-tokens.mjs` to `src/theme/tokens.css`). Colors that upstream writes as fixed Compose constants (`Color.White`, `Color.Gray`, `Color.Black`, red, green, blue and the log-level colors) are emitted by the same generator as `--fx-*` variables. They are literals in the generator, not entries in `docs/spec/design-tokens.json` (`--fx-white` on main; the others on `integration`).
- Type scale, card shapes, focus ring color, drawer colors and sizes: taken from the Kotlin and from the `androidx.tv` library source (`src/ui/LIB_DEFAULTS.md`). One caveat: the library source was read from its main branch, because no tag exists for the version Wholphin uses (1.1.0-alpha01), so a few values may differ slightly.
- Page structure: nav drawer, home header plus rows, card types, dialogs, and the order and conditions of context-menu entries.
- Strings: the same Android string names as keys, all upstream translations converted (`tools/gen-strings.ts`, `src/i18n/locales/`).
- Data: the same Jellyfin API calls, the same display-preference client name (`Wholphin`), and the same JSON format for home rows and "removed from Next Up", so settings are shared with the TV app on the same server.
- Playback decisions: stream choice, track selection, device-profile rules, media segments, Next Up and progress reporting are ports of the Kotlin (unit tests transcribed from the upstream tests).

## 9. Playback

Evidence: the engine was built and run against every test codec file and several items on the real server (see `PLAYBACK_MATRIX.md` for the numbers and the honest failures). The on-screen player was then built on top of it (`src/features/playback/PlayerView.tsx` and `src/features/playback/ui/`) and driven in Edge at 1920x1080 with mouse and keyboard and at 390x844 and 844x390 with emulated touch, on the throwaway test server and on one episode of the real server (the episode was marked played during the test; the builder reset it and confirmed the reset). Three independent reviewers examined playback, and a fixer handled their 19 findings (13 fixed, 3 rejected, 3 deferred), re-checking in headless Edge. At the branch gates and again after the final merge, an H.264 item played inside the production container under its Content Security Policy with no violations. On `integration` an end-to-end test plays an H.264 item, pauses, seeks and exits. Not verified: Safari or iOS (the native-HLS backend; an iPhone uses its native video fullscreen, where the overlay is not shown), Firefox and Chrome with the on-screen player, real touch hardware and the orientation lock, hardware media keys, HDR displays, hardware HEVC direct play (not testable in a headless browser; only the transcode path ran), a successful subtitle search and download (only the refused request and mocked unit tests ran), a silent decode failure (only forced failures), cinema-mode intros, trailers inside the player, the wake lock, seeking in a high-resolution HDR file on the real server (deferred, to avoid heavy transcodes there), and whether version and track choices made on a detail page are honored in a real playback session (code reading and shared tests only).

The release round (state "release") changed two things here, both asked for by the owner (DECISIONS O-34). The player's layout was rebuilt after Jellyfin's own web player: nothing darkens the picture, and one low strip at the bottom edge carries the controls (T-60). And the device profile was made to let the browser play far more by itself: for desktop Chromium the server no longer repackages a Matroska file, and no longer re-encodes the picture for PGS subtitles or for HDR10 (T-59). Evidence for the layout: the builder's measurements and pictures in five window sizes, in English and Hebrew, end-to-end tests (`e2e/specs/playback-layout.spec.ts`) and an independent verifier's own script, all in headless Edge on the throwaway test server. Evidence for direct play: the playback answers of the throwaway test server and, read-only, of the real server for every case before and after, built from the app's own profile inside headless Edge, Chrome, Firefox and WebKit; real playback of the test files with picture and sound measured; end-to-end tests (`e2e/specs/playback-direct.spec.ts`); and an independent verifier's repeat in the four browsers. The table per file is in `PLAYBACK_MATRIX.md`, section "Playing without the server converting". Not verified for either: a real phone, real Safari and iOS, a released Firefox (only Playwright's build), a display that is HDR, a browser that decodes AC-3 or E-AC-3 (none was available), Dolby Vision files, large real PGS tracks, and any stream from the real server with the new code by an agent.

The maintenance rounds (state "maintenance") changed the strip again on the owner's requests: fixed button positions, clock times, a softer gradient and a favourite button (`c2316a4`), the two side button groups swapped (`255bff6`), subtitle style options inside the player (`e31ba4b`) and compact Settings sheets (`cf29a99`, `509db33`).
